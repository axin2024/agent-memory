# 验收记录

2026-11-26，Windows、Go 1.26.0、MySQL 8.4.13。服务测试和真实 HTTP 测试分别使用独立临时模式。验收覆盖 [编号场景](requirements/04-验收与运营-prd.md)。

| 用例 | 可复核结果 |
| --- | --- |
| AC-01 | 两个授权助手召回同一邮件偏好，来源摘要相同。 |
| AC-02 | 第三个助手、另一租户的助手及审计员查询均被拒绝。 |
| AC-03 | 同一来源重试返回原来源和候选，MySQL 只有一条来源记录。 |
| AC-04 | 内容变化返回 409 并进入本人队列。相同冲突重试返回相同回执。HTTP 测试覆盖 51 条分页、确认保留原记录、拒绝另一用户和租户操作。 |
| AC-05 | 候选包含长期偏好原句、来源定位及候选值。裁决页同时返回当前事实的证据。 |
| AC-06 | 引用朋友偏好的来源未生成候选，敏感模式命中的来源不保存正文。 |
| AC-07 | 短信偏好通过裁决后，历史时点仍能读到已结束的邮件版本。 |
| AC-08 | 晚到的旧事件标为陈旧，保持已采信版本。 |
| AC-09 | 两个助手得到短信及修订会话、来源摘要、原句。 |
| AC-10 | 撤回其中一个助手的授权后，历史时点查询也被拒绝。 |
| AC-11 | 遗忘后重送原来源、冲突变化或旧时间的新编号均被拒绝。MySQL 清除对应冲突记录。 |
| AC-12 | 旧快照确实持有事实和冲突，恢复进程追到签名日志水位 3 后，已忘事实、冲突、已撤授权和分享均未恢复。 |
| AC-13 | 用户再纠正一次后，两个助手都得到第三版及用户纠正来源。 |
| AC-14 | 撤回被选中的分享后旧链接返回 404，遗忘同时使其余相关链接失效。 |
| AC-15 | 100 组中 50 次预期命中均含正确来源，25 组已忘，25 组权限不足，无预期命中缺失。 |
| AC-16 | 每组另有一个同租户不同用户和一个跨租户的更高匹配候选。两类泄露均为 0。 |

100 组单线程串行召回的 P95 为 9.378 ms，逐条回读见 [召回记录](results/recall.json)。另测了错误密钥、日志并发打开和截断日志，均得到恢复错误。

用已发行的 `v1.0.0` 源码构建旧程序并写入，使用 MySQL 转储恢复到独立模式。新程序先拒绝未经迁移的库，重复执行迁移成功，导出结果与旧版一致。旧来源可重试，变更内容进入冲突队列，两位助手均能召回原事实，遗忘后队列为空。[升级记录](results/upgrade.json)

真实模型使用 llama.cpp b12686 与 Qwen2.5-0.5B-Instruct Q4_K_M，在 CPU 上以 4 线程处理 5 条文本。通知与时区两条进入待审，语言和计量单位未提取，一条临时请求响应未通过校验。自动采信为 0。两条待审用例耗时 856 ms 和 937 ms，失败用例耗时 2419 ms。输入、任务编号、输出状态、权重摘要与 Token 用量见 [模型实测](results/model.json)。

独立 HTTP 模型夹具验证了可查任务、超时租约重领、失败重试、精确证据片段及推理过程中撤权。批量裁决回执同时包含已拒绝、版本冲突和找不到记录三个结果。遗忘进度由本人读取，其他用户和租户无法读取。

```powershell
pwsh -File scripts/test-mysql.ps1 -MySQLBin C:/mysql-8.4/bin -Scenario All
pwsh -File scripts/test-mysql.ps1 -MySQLBin C:/mysql-8.4/bin -Scenario Upgrade -PreviousBinary C:/releases/agent-memory-v1.0.0.exe
```

设置 `MEMORY_TEST_MODEL_URL` 和 `MEMORY_TEST_MODEL` 可复跑真实模型场景。[模型来源](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF)
