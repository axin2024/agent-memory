# 跨会话智能体记忆服务｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 应用与同意 | subject(tenant,external_id), consent(subject,app,purpose,until_at) | 用户指明哪些助手可写、可读及用途，授权可到期；查询及来源展示再次核验范围。 |
| 来源写入 | source_event(tenant,app,key,hash), evidence(source,span,expiry) | 保存必要来源定位、时间与最小证据；原文保留期限独立配置，重复来源不能复活已撤销内容。 |
| 候选抽取 | extraction(source,model_rev), candidate(subject,fact_key,confidence) | 区分陈述、推测、一次性请求与长期偏好，缺少主体或证据时保留候选并允许用户拒绝。 |
| 冲突与版本 | fact(subject,key,scope), fact_ver(fact,from_at,to_at,source) | 按事件发生时间与来源权威比较；不同场景可并存，无法自动判断时呈现双份证据。 |
| 召回与解释 | recall_log(subject,purpose,policy_rev), evidence_link(fact_ver,source) | 以 MySQL 候选与权限为基线，文本或派生相似索引提供排序；返回前核查最新授权和事实版本。 |
| 删除与遗忘 | forget_request(subject,scope,watermark), purge_step(request,target,state) | 先撤销读取和缓存，再清派生索引与原文，保留不含事实正文的必要抑制标记和清理进度。 |
| 用户工作台 | user_edit(fact,rev,actor), export_job(subject,scope,digest) | 用户可见采信理由、有效范围及来源，纠正生成版本；导出只包含本人当前可见资料。 |
| 质量与维护 | eval_case(dataset,subject,wanted), eval_result(run,case_id,outcome) | 按用户划分保留集，对冲突、遗漏、已删和不同租户分别报告指标，区分真实模型与回放。 |

## 事务、索引与对账

- **身份与约束**　租户＋主体＋事实键＋场景定位事实，来源号幂等，遗忘边界按主体与来源水位记录。
- **业务索引**　按主体、用途、有效区间查召回候选，按清理状态扫描遗忘任务。
- **数据生命周期**　正文及派生索引异步清除，备份恢复先重施抑制标记，遗忘凭证避免存放被删正文。

按租户、用户及事实键串行修订；删除先推进授权代际并设抑制旧来源的标记，再清派生副本。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

写入附来源、授权范围与时间；召回附证据和有效期，删除回执可查询清理进度；支持真实抽取器与离线夹具。

写入提供租户、主体、应用、来源身份和适用时间；输出候选事实、信心、冲突及确认证据。

召回带用途、时间和请求主体，返回有效事实、版本及来源。遗忘返回操作号和派生清理水位。

## 数据恢复与核验

在隔离环境恢复 MySQL 和引用清单，校验样例的源对象、派生关系及最终结果。恢复后应能回答以下问题。返回短信及新来源，展示旧偏好已失效；删除后两个助手均不再召回，旧来源重放不能复活记录。
