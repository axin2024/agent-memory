# 跨会话智能体记忆服务｜状态与操作契约

## 记忆事实的生命周期

建议→确认或自动采信→有效→被替代、到期或遗忘。用户纠正优先，重算只读取仍被授权的来源。

## 权限与操作者

应用身份提交用户授权的会话，用户可查改删本人记忆，租户管理员配置保留期，审计员仅看最小操作摘要。 在待审批与已完成状态分别检查读写范围，委托与代办保留真实操作者身份。

## 两个关键交互

1. 写入提供租户、主体、应用、来源身份和适用时间；输出候选事实、信心、冲突及确认证据。
2. 召回带用途、时间和请求主体，返回有效事实、版本及来源。遗忘返回操作号和派生清理水位。

## 业务操作与异常回执

| 操作域 | 在当前数据上的处理 | 冲突、拒绝或降级行为 |
|---|---|---|
| 应用与同意 | 用户指明哪些助手可写、可读及用途，授权可到期；查询及来源展示再次核验范围。 | 未获授权第三助手按用户号查询返回空或拒绝。 |
| 来源写入 | 保存必要来源定位、时间与最小证据；原文保留期限独立配置，重复来源不能复活已撤销内容。 | 同一来源号出现不同内容进入冲突队列。 |
| 候选抽取 | 区分陈述、推测、一次性请求与长期偏好，缺少主体或证据时保留候选并允许用户拒绝。 | 引用别人的偏好不能记成用户本人偏好。 |
| 冲突与版本 | 按事件发生时间与来源权威比较；不同场景可并存，无法自动判断时呈现双份证据。 | 晚到旧对话不推翻已经确认的新值。 |
| 召回与解释 | 以 MySQL 候选与权限为基线，文本或派生相似索引提供排序；返回前核查最新授权和事实版本。 | 历史时点查询仍受当前可见权限限制。 |
| 删除与遗忘 | 先撤销读取和缓存，再清派生索引与原文，保留不含事实正文的必要抑制标记和清理进度。 | 恢复旧备份时先重施遗忘水位再开放读取。 |
| 用户工作台 | 用户可见采信理由、有效范围及来源，纠正生成版本；导出只包含本人当前可见资料。 | 分享链接撤回后不再显示任何旧事实。 |
| 质量与维护 | 按用户划分保留集，对冲突、遗漏、已删和不同租户分别报告指标，区分真实模型与回放。 | 无关用户记忆即使语义更相似也不可返回。 |

## 失联、中断及恢复

按租户、用户及事实键串行修订；删除先推进授权代际并设抑制旧来源的标记，再清派生副本。 中断后先查询最后一个已持久的业务标记，再决定安全重试、补偿或人工复核。对外回执携带对象身份及业务版本。批量操作允许逐项查看成功、失败和未开始。

## 发布级业务断言

恢复备份前重施删除水位，禁止从陈旧来源重新派生已遗忘事实；审计仅保留必要摘要。 返回短信及新来源，展示旧偏好已失效；删除后两个助手均不再召回，旧来源重放不能复活记录。
